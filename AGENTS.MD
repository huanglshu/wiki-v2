# AGENTS.MD

## Project Overview

This repository is a Wiki.js 2.x application. It contains a Node.js
Express/GraphQL server, a Vue 2/Vuetify 2 client, server-side rendering and
search/storage modules, and generated frontend assets.

Use the existing project structure and conventions before introducing a new
abstraction. Keep changes scoped to the requested behavior. Do not revert or
reformat unrelated work already present in the worktree.

## Toolchain

- Use Node.js 24.12.0, matching `.nvmrc`. The currently available `node` and
  `npx` commands run this version.
- Use the committed `yarn.lock` and existing dependency versions. Do not update
  dependencies unless the task requires it.
- Source files use UTF-8, LF line endings, and two-space indentation. The
  existing editor configuration is authoritative.
- This is a Windows PowerShell checkout. Use PowerShell-native commands when
  terminal wrappers behave unexpectedly, and quote paths containing spaces.

## Common Commands

Run commands from the repository root. Use focused checks while iterating.

```powershell
# Start the development server and Webpack watcher
yarn dev

# Start from the built application
yarn start

# Focused JavaScript/Vue lint check
npx eslint --format codeframe path/to/file.vue

# Full JavaScript/Vue lint check
npx eslint --format codeframe --ext .js,.vue .

# Pug templates and the repository Jest tests
npx pug-lint server/views
npx jest

# Verify Cypress against a running local server
yarn cypress:open
```

The production build script is `yarn build`. It sets the required
`--openssl-legacy-provider` Node option. Do not invoke the production Webpack
configuration directly without that option on modern Node. A development
Webpack invocation also needs the option when it is not launched through
`yarn dev`.

## Repository Map

- `client/components/admin.vue`: administrator shell, navigation, and router.
- `client/components/admin/`: administrator pages and editor components.
- `client/components/common/`: shared client UI components.
- `client/helpers/admin-module.js`: i18n display adapter for dynamic

- `client/modules/`: client boot and i18next/localization setup.
- `client/graph/`: GraphQL documents used by the client.
- `client/store/`: Vuex state.

- `dev/webpack/`: development and production Webpack configuration.

## Admin UI And Localization

For requested administrator UI changes, search the actual Vue source first.
Static visible strings should be changed in the relevant `.vue` template.
When module metadata arrives from the server, apply display translations at the
client boundary rather than editing module definitions or relying on missing
translation keys.

`data/sideload/zh.json` is the single source of truth for all Chinese UI copy.
Every new or changed Chinese label, title, subtitle, hint, placeholder, button,
notification, confirmation, empty state, or other user-visible string must be
defined in that file and referenced by a translation key. Use `$t(...)` or the
`i18next` component in Vue files. Module definitions should expose i18n keys,
and the client should resolve them through the active i18n instance. Do not add
new hard-coded Chinese UI text to Vue templates, JavaScript mappings, server
definitions, or GraphQL responses. Keep the existing English YAML values as
fallbacks and identifiers; they are not user-visible Chinese copy.

Use `client/helpers/admin-module.js` through its exported translation
functions for dynamic module titles, descriptions, property labels, hints,
enums, and actions. Preserve internal keys, GraphQL values, routes, permission
strings, and saved enum values. When displaying translated enum labels, use an
object with `{ text, value }` where the underlying API needs the original value.

Local YAML files under `server/locales/` are developer overrides and are
gitignored. Do not treat those files as a committed fix. Prefer explicit Chinese
UI text or a committed display mapping when the requested interface must remain
Chinese independently of the loaded language pack.

For the admin title shown in the top bar, use the existing dedicated class in
`client/components/admin.vue`. Its required presentation is 20px, white, bold.
Keep the selector scoped to the admin navigation title so it does not change
other headings.

## Generated And Local Files

Do not hand-edit generated assets or local runtime configuration:

- `assets/`: generated by Webpack.
- `server/views/master.pug`, `server/views/legacy/master.pug`,
  `server/views/setup.pug`: generated templates.
- `.webpack-cache/`: build cache.
- `config.yml`: local configuration and gitignored.
- `data/`, uploaded content, logs, and `server/locales/**/*.yml`: local runtime
  data and overrides.

When a source change needs compiled output for the current development server,
let the existing watcher rebuild it or use the project scripts. Never use a
generated bundle as the source of truth.

## Editing Rules

- Read surrounding code and follow its Vue/Pug, GraphQL, Vuex, and module
  patterns.
- Preserve user changes in a dirty worktree. In particular, do not reset or
  overwrite an existing `yarn.lock` change unless explicitly asked.
- Avoid broad formatting-only edits and unrelated refactors.
- Keep data keys and API payloads stable when translating labels.
- Make controls and text responsive so longer Chinese labels do not overlap,
  clip, or shift fixed toolbar/grid elements.
- Add tests only where the risk and existing test structure justify them. For
  narrow UI copy changes, run focused ESLint and inspect the affected template.
- Put client Jest tests under `client/test/`, mirroring the relevant `client/`
  source paths instead of placing them next to source files.

## Verification

Before finishing a change, run the narrowest relevant checks and report what was
verified. For Vue files, use ESLint on the changed files. For shared behavior,
also run the relevant Jest tests. If a full build or test is blocked by the
environment, state the exact blocker and any focused checks that did pass.

## 管理后台与本地化

修改管理后台界面时，应先搜索并检查实际的 Vue 源文件。静态可见文案应在
对应的 `.vue` 模板中修改。模块元数据由服务端返回时，应在客户端展示层应用
翻译，而不是修改模块定义，也不要依赖缺失的翻译键。

`data/sideload/zh.json` 是所有中文界面文案的唯一来源。新增或修改中文标签、
标题、副标题、提示、占位符、按钮、通知、确认信息、空状态或其他用户可见文本，
都必须在 `zh.json` 中定义并通过翻译键引用。Vue 文件使用 `$t(...)` 或
`i18next` 组件。模块定义应声明 i18n 键名，客户端通过当前 i18n 实例解析。
不得在 Vue 模板、JavaScript 映射、服务端定义或 GraphQL 返回值中新增硬编码
中文界面文案。现有英文 YAML 值仅作为回退和标识符，不是中文展示文案。

使用 `client/helpers/admin-module.js` 导出的翻译函数处理动态模块的标题、
说明、属性名、提示、枚举和操作。必须保留内部键、GraphQL 值、路由、权限
字符串和保存所需的枚举值。翻译枚举显示文本时，如果底层 API 需要原值，
应使用 `{ text, value }` 对象。

`server/locales/` 下的本地 YAML 文件是开发者的本地覆盖文件，并已被
Git 忽略。不要把这类文件当作可提交的修复。如果界面必须独立于语言包保持
中文，应优先使用明确的 Chinese UI 文案或提交到仓库的显示映射。

后台顶部标题使用 `client/components/admin.vue` 中的专用类。其样式要求为
20px、白色、加粗。选择器必须仅作用于管理后台导航标题，不能影响其他标题。

## 编辑规则

- 先阅读周边代码，遵循现有的 Vue/Pug、GraphQL、Vuex 和模块模式。
- 保留工作区中用户已有的修改。特别是未经明确要求，不得重置或覆盖现有的
  `yarn.lock` 修改。
- 避免大范围仅格式化改动和无关重构。
- 翻译标签时，保持数据键和 API 载荷稳定。
- 控件和文字应具备响应式适配，较长的中文标签不能重叠、裁切或导致固定
  工具栏和网格布局跳动。
- 仅在风险和现有测试结构足以支撑时添加测试。对于范围较小的界面文案改动，
  运行针对性的 ESLint 并检查受影响的模板。
- 客户端 Jest 测试统一放在 `client/test/`，按 `client/` 源码目录结构镜像
  组织，不再与源码文件放在同一目录。

## 验证

结束改动前，运行与改动最相关的检查，并说明验证内容。对于 Vue 文件，必须
对修改过的文件运行 ESLint。对于共享行为，还应运行相关的 Jest 测试。如果
完整构建或测试因环境问题受阻，应说明具体阻塞原因以及已通过的针对性检查。
